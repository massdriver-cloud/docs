Lets CI runs from a GitHub or GitLab repository act as a service account, with no token stored
in the CI platform.

A run requests an OIDC ID token from its platform with the audience
`massdriver:<organization id>`, and sends it to `POST /oauth/token` with the grant type
`urn:ietf:params:oauth:grant-type:token-exchange`. When the token comes from `issuer` and
carries every claim in `claims` with the same value, the run receives a short-lived access
token for the service account. The run then has the service account's permissions.

**GitHub Actions** — the job needs `permissions: id-token: write`. The rule must include
`repository_owner_id`. Add `repository_id` to limit it to one repository, and `ref` (for example
`refs/heads/main`) or `environment` to limit it to one branch or deployment environment.

**GitLab CI** — the job requests the token with `id_tokens`. The rule must include
`namespace_id`. Add `project_id` to limit it to one project, and `ref` or `ref_protected` to
limit it to one branch or to protected branches.

Use numeric IDs, not names. A deleted repository or owner name can be registered again by
someone else.
