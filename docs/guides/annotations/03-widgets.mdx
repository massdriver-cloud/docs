# Widgets

:::caution Alpha
This feature is alpha. Names, fields, and behavior can change or be removed at any time without notice.
:::

A widget is a built-in picture that shows [stash](/guides/stash) values. There are two ways to show one.

- **Automatic.** Write a well-known `md/v1/` key. Everyone with `stash:view` on the stash sees the widget. You do not set anything up.
- **Added by you.** Right-click the canvas, choose **Add widget**, and choose a stash entry for each input. Only you see it. For a step-by-step example, see [Add a widget from your own keys](/guides/annotations#add-a-widget-from-your-own-keys).

When you add a widget in the same place as an automatic one, you see your widget. If your widget has no value, you see the automatic one.

Each widget has a tooltip. It shows the widget's label and value, for example `Connection pool: 37 of 100 (37%)`, and when the stash entry was last updated, for example `Updated 2m ago`. The label is the stash entry's label, which you set with `--label`. A usage bar without an entry label uses the `label` field of its value. Otherwise the widget uses a default label: `Health`, `Traffic`, or `Usage`.

To hide automatic widgets, click the **Widgets** button in the canvas toolbar, after the inactive instances button. The setting is saved in your browser and applies only to you. Widgets that you add still show.

## Well-known keys

| Key | Set on | Format | Widget |
|---|---|---|---|
| `md/v1/health` | Instance | TEXT | [Status dot](#status-dot) |
| `md/v1/usage` | Instance | JSON | [Usage bar](#usage-bar) |
| `md/v1/traffic` | Instance | JSON | [Traffic](#traffic) on the lines that leave the instance |
| `md/v1/banner` | Environment | JSON | [Banner](#banner) |
| `md/v1/links` | Environment | JSON | [Header links](#header-links) |

The `md/` prefix is reserved. The server checks each write to an `md/` key. See [Well-known keys](/guides/stash/well-known-keys) for the rules and the full schema of each key.

## Status dot

A colored dot in the header of an instance node. The tooltip shows the label and the value, for example `Health: degraded`.

### Automatic: `md/v1/health`

Set on the instance. Format: TEXT.

The value must match the [`md/v1/health` schema](/guides/stash/well-known-keys#mdv1health).

```bash
mass alpha stash set billing-dev-app.md/v1/health degraded
```

### What it looks like

| State | Looks like | Value | Meaning |
|---|---|---|---|
| Healthy | <StatusDotState tone="success" label="Status dot healthy: a green dot" /> | `healthy`, `ok`, or `up` | A green dot. |
| Degraded | <StatusDotState tone="warning" label="Status dot degraded: an amber dot" /> | `degraded`, `warning`, or `recovering` | An amber dot. |
| Down | <StatusDotState tone="error" label="Status dot down: a red dot" /> | `down`, `failed`, or `error` | A red dot. |
| Unknown | <StatusDotState tone="neutral" label="Status dot with an unknown value: a gray dot" /> | any other text | A gray dot. |

The match ignores case and spaces at each end.

### Use your own stash keys

Right-click an instance node and choose **Add widget** > **Status dot**.

| Input | Type | Required | Example key | Path |
|---|---|---|---|---|
| `state` | string | yes | `status/health` on the instance (TEXT) | none |

## Usage bar

A thin bar at the bottom of an instance node. The label is on the left of the bar. The value and the limit, for example `37 / 100`, are on the right.

### Automatic: `md/v1/usage`

Set on the instance. Format: JSON.

The value must match the [`md/v1/usage` schema](/guides/stash/well-known-keys#mdv1usage).

| Field | Meaning |
|---|---|
| `value` | The amount in use. |
| `max` | The limit. |
| `label` | Optional. The label on the left of the bar, when the entry has no `--label`. |

```bash
mass alpha stash set billing-dev-app.md/v1/usage '{"value": 37, "max": 100, "label": "connections"}' --format json
```

### What it looks like

| State | Looks like | Value | Meaning |
|---|---|---|---|
| Under 80% | <UsageBarState percent={37} tone="teal" name="connections" text="37 / 100" label="Usage bar at 37 percent: a teal bar with the label connections on the left and 37 / 100 on the right" /> | `{"value": 37, "max": 100, "label": "connections"}` | A teal bar. |
| 80% to 94% | <UsageBarState percent={86} tone="warning" name="connections" text="86 / 100" label="Usage bar at 86 percent: an amber bar with the label connections on the left and 86 / 100 on the right" /> | `{"value": 86, "max": 100, "label": "connections"}` | An amber bar. |
| 95% or more | <UsageBarState percent={97} tone="error" name="connections" text="97 / 100" label="Usage bar at 97 percent: a red bar with the label connections on the left and 97 / 100 on the right" /> | `{"value": 97, "max": 100, "label": "connections"}` | A red bar. |

A value above `max` fills the bar.

### Use your own stash keys

Right-click an instance node and choose **Add widget** > **Usage bar**. Each input can read a different key. For example, two TEXT entries:

```bash
mass alpha stash set billing-dev-app.db/connections 37
mass alpha stash set billing-dev-app.db/max_connections 100
```

| Input | Type | Required | Example key | Path |
|---|---|---|---|---|
| `value` | number | yes | `db/connections` on the instance | none |
| `max` | number | yes | `db/max_connections` on the instance | none |
| `label` | string | no | none | none |

A usage bar that you add with a `max` of 0 or less does not show.

## Traffic

The traffic on a line between two instances, shown as the width, color, and movement of the line. A short label on the line shows the rate, the errors, the p95 latency, and "stale" when the data is old. For example, `240 rps · 2 err · 180 ms`. The label leaves out the errors when there are none, and the latency when there is no value.

### Automatic: `md/v1/traffic`

Set on the instance that sends the traffic. Format: JSON. Every line that leaves that instance shows the traffic.

The value must match the [`md/v1/traffic` schema](/guides/stash/well-known-keys#mdv1traffic).

| Field | Meaning | Input |
|---|---|---|
| `rps` | Requests per second. | `rate` |
| `errors_5m` | Errors in the last 5 minutes. | `errors` |
| `p95_ms` | Optional. p95 latency in milliseconds. | `latency` |

```bash
mass alpha stash set billing-dev-app.md/v1/traffic '{"rps": 240, "errors_5m": 2, "p95_ms": 180}' --format json
```

Write the entry on a schedule. When it is not updated for 10 minutes, the line shows as stale. Add `--ttl` to remove the entry, and the widget, after a time.

### What it looks like

| State | Looks like | Value | Meaning |
|---|---|---|---|
| Off | <TrafficState state="off" label="Traffic off: a plain gray line with no label" /> | key missing or expired | The line shows as usual. |
| Idle | <TrafficState state="idle" label="Traffic idle: a thin gray dashed line with a 0 rps label" /> | `{"rps": 0, "errors_5m": 0}` | Rate 0. A thin gray dashed line. |
| Flowing | <TrafficState state="flowing" label="Traffic flowing: a thick teal moving line with a 240 rps, 180 ms label" /> | `{"rps": 240, "errors_5m": 0, "p95_ms": 180}` | Rate above 0 and no errors. A teal line. |
| Some errors | <TrafficState state="someErrors" label="Traffic with some errors: an amber line with a 240 rps, 3 err, 180 ms label" /> | `{"rps": 240, "errors_5m": 3, "p95_ms": 180}` | 1 to 9 errors. An amber line. |
| Many errors | <TrafficState state="manyErrors" label="Traffic with many errors: a red line with a 240 rps, 42 err, 180 ms label" /> | `{"rps": 240, "errors_5m": 42, "p95_ms": 180}` | 10 or more errors. A red line. |
| Stale | <TrafficState state="stale" label="Stale traffic: a teal line at half opacity with a stale label" /> | not updated for 10 minutes | The line fades to half opacity. |

The line width follows the rate:

| Rate | Width |
|---|---|
| under 10 | 3px |
| 10 to 99 | 4px |
| 100 to 999 | 6px |
| 1000 or more | 8px |

On a line with traffic, dashes move from the source instance to the destination instance. Higher rates move faster. When your system asks for reduced motion, the line is solid and does not move.

### Use your own stash keys

Right-click a line and choose **Add widget** > **Traffic**. You can read from the `source` or the `destination` instance.

| Input | Type | Required | Example key | Path |
|---|---|---|---|---|
| `rate` | number | yes | `stats/traffic` on `destination` (JSON) | `rps` |
| `errors` | integer | yes | `stats/traffic` on `destination` (JSON) | `errors_5m` |
| `latency` | number | no | `stats/traffic` on `destination` (JSON) | `p95_ms` |

## Banner

A message across the top of the environment canvas. Banners stack.

### Automatic: `md/v1/banner`

Set on the environment. Format: JSON.

The value must match the [`md/v1/banner` schema](/guides/stash/well-known-keys#mdv1banner).

| Field | Meaning |
|---|---|
| `message` | The banner text. |
| `level` | Optional. `info` (blue, the default), `warning` (amber), or `error` (red). |

```bash
mass alpha stash set billing-dev.md/v1/banner '{"message": "Deploy freeze until Friday", "level": "warning"}' --format json
```

### What it looks like

| State | Looks like | Value | Meaning |
|---|---|---|---|
| Info | <BannerState levels={["info"]} label="Info banner: a blue strip" /> | `{"message": "Database upgrade tonight"}` | A blue banner. |
| Warning | <BannerState levels={["warning"]} label="Warning banner: an amber strip" /> | `{"message": "Deploy freeze until Friday", "level": "warning"}` | An amber banner. |
| Error | <BannerState levels={["error"]} label="Error banner: a red strip" /> | `{"message": "Payments API is down", "level": "error"}` | A red banner. |
| Two banners | <BannerState levels={["warning", "info"]} label="Two banners stacked: an amber strip above a blue strip" /> | `md/v1/banner` and a banner that you added | Banners stack, one per widget. |

### Use your own stash keys

Right-click an empty part of the canvas and choose **Add widget** > **Banner**. For example, a short-lived TEXT entry:

```bash
mass alpha stash set billing-dev.status/maintenance "Database upgrade tonight" --ttl 86400
```

| Input | Type | Required | Example key | Path |
|---|---|---|---|---|
| `message` | string | yes | `status/maintenance` on the environment | none |
| `level` | string | no | none | none |

A banner that you add with a `level` that is not `info`, `warning`, or `error` shows as `info`.

## Header links

Link buttons in the environment header, such as a dashboard or a runbook. A button opens its URL in a new tab.

### Automatic: `md/v1/links`

Set on the environment. Format: JSON. Each item in `links` is one button.

The value must match the [`md/v1/links` schema](/guides/stash/well-known-keys#mdv1links).

| Field | Meaning |
|---|---|
| `links[].label` | The button text. |
| `links[].url` | An `http` or `https` URL. |

```bash
mass alpha stash set billing-dev.md/v1/links '{"links": [{"label": "Shop", "url": "https://shop.example.com"}, {"label": "Grafana", "url": "https://grafana.example.com/d/billing"}]}' --format json
```

### What it looks like

| State | Looks like | Value | Meaning |
|---|---|---|---|
| One link | <HeaderLinkState links={["Shop"]} label="One header link button labeled Shop" /> | `{"links": [{"label": "Shop", "url": "https://shop.example.com"}]}` | One button. |
| Two links | <HeaderLinkState links={["Shop", "Grafana"]} label="Two header link buttons, Shop and Grafana" /> | two items in `links` | One button per item. |
| Not an http URL | <HeaderLinkState links={["Shop"]} label="Only the Shop button shows, because the other link URL is not http or https" /> | `{"links": [{"label": "Shop", "url": "https://shop.example.com"}, {"label": "Files", "url": "ftp://files.example.com"}]}` | The server rejects this value for `md/v1/links`. In a header link widget that you add, the link with the `ftp` URL does not show and the other links do. |

### Use your own stash keys

Right-click an empty part of the canvas and choose **Add widget** > **Header link**. The widget has one input, `links`. Point it at a JSON entry that holds a list of links in the same shape as `md/v1/links`:

```bash
mass alpha stash set billing-dev.links '{"links": [{"label": "Shop", "url": "https://shop.example.com"}]}' --format json --label "Links"
```

| Input | Type | Required | Example key | Path |
|---|---|---|---|---|
| `links` | array | yes | `links` on the environment (JSON) | `links` |

Each item is one button. The first 8 links with an `http` or `https` `url` show. A link without a `label` shows the URL host.

## Inputs of a widget that you add

The widget editor has one row for each input. In each row:

1. **Stash**: choose whose stash to read.
2. **Key**: choose a key from the list, or type one. You can type a key that has no value yet.
3. **Path**: for a JSON entry, choose a field, or **Whole value**. When the key has no value yet, type the fields, separated by commas.

The last column shows the current value, such as `✓ degraded`, or why the input has no value:

| Status | Meaning |
|---|---|
| **Choose a key** | The input is required and has no key. |
| **Optional** | The input is optional and has no key. |
| **No value yet** | The key has no value, has expired, or is sensitive. |
| **Not a valid key** | The key has characters other than letters, digits, and `_ . / -`. |
| **Not a number**, **Not a whole number**, **Not text**, **Not a list** | The value has the wrong type. |
| **Not a JSON entry** | You chose a path, but the entry is TEXT. |
| **Path not found** | The JSON value does not have that field. |

You can save the widget when every required input has a valid key. The widget shows only when every required input has a value of the right type.

Open **Data this widget reads** at the top of the editor to see the inputs, the automatic `md/v1/` key and its fields, and a `mass alpha stash set` command. Under **Or use your own stash keys**, the editor gives example entries. **Then set the inputs** tells you which key and path to choose for each input.

| Input type | Accepted values |
|---|---|
| number | A JSON number, or a text value such as `42`, `-3`, or `12.5` |
| integer | A whole number, as a JSON number or as text such as `3` |
| string | Text |
| array | A JSON list |

| Added to | Stashes you can choose |
|---|---|
| An instance | `project`, `environment`, `component`, `instance` |
| A line | `project`, `environment`, `source`, `destination` |
| An environment | `project`, `environment` |
